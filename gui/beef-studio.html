Cross-sections / materials

Each maps to a fe.Section(...). Blank optional fields fall back to beef defaults. In 2D only I_y is used for bending.

Constraints

To ground = support (leave “slave” empty) → fe.Constraint([masters], dofs=…). Node-to-node ties masters↔slaves. DOFs: all, trans, rot, or indices like 0,1,2.

Features — springs, dashpots, point masses

Maps to fe.Spring / fe.Dashpot / fe.PointMass. One node ⇒ grounded element at that DOF; two nodes ⇒ connects them. DOFs as indices, e.g. 0,1,2.

Loads

Maps to fe.Force(node_labels, dofs, amplitudes, t=…). Constant: static value. Ramp: 0→amp over t (good for nonlinear static). History: expression a(t) sampled on the analysis time axis (for dynamics).

BEEF Studio

A complete graphical front-end for beef (BEam Elements Framework) by Knut A. Kvåle. Build a beam finite-element model visually, generate ready-to-run beef Python, and execute every analysis the library offers right in your browser.

Workflow

  • Model — choose 2D/3D, add nodes & elements (or use the generators).
  • Sections — define cross-sections/materials (E, A, I_y, I_z, J…).
  • Supports — constraints to ground or node-to-node ties.
  • Features — springs, dashpots, point masses.
  • Loads — nodal forces/moments: constant, ramp, or time-history.
  • Analysis — pick the solver and parameters, then ▶ Run.

DOF indices

2D node: 0=ux, 1=uy, 2=rz.   3D node: 0=ux, 1=uy, 2=uz, 3=rx, 4=ry, 5=rz.

Running

The Code view (right panel after a run, or the “Py” button) shows the exact beef script. The runner loads Pyodide + NumPy/SciPy from a CDN the first time (needs internet); the bundled beef source then runs locally. Everything else — building, visualizing, code export — works offline.

beef is MIT-licensed. This GUI bundles its compute modules (not the pyvista/trame plotting stack) to run analyses in the browser.
