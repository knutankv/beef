Cross-sections / materials

Each maps to a fe.Section(...). Blank optional fields fall back to beef defaults. In 2D only I_y is used for bending.

Constraints

To ground = support (leave “slave” empty) → fe.Constraint([masters], dofs=…). Node-to-node ties masters↔slaves. DOFs: all, trans, rot, or indices like 0,1,2.

Features — springs, dashpots, masses, matrices

Maps to fe.Spring / fe.Dashpot / fe.PointMass. One node ⇒ grounded element at that DOF; two nodes ⇒ connects them. DOFs as indices, e.g. 0,1,2. Matrix maps to fe.CustomMatrix: a full (coupled) stiffness, damping or mass matrix over the listed node(s) × DOFs, e.g. a 6×6 pontoon mass or a spring in a rotated axis system.

Loads

Maps to fe.Force(node_labels, dofs, amplitudes, t=…). Constant: static value. Ramp: 0→amp over t (good for nonlinear static). History: expression a(t) sampled on the analysis time axis (for dynamics).

Element loads

Constant distributed load on elements, converted to equivalent nodal forces (and end moments) with fe.create_nodal_load_from_element_load: self weight from the sections, a constant mass per length, a total mass, or an expression in sec giving the load per length.

BEEF GUI

A graphical front end for beef (BEam Elements Framework). The page talks to a small Python server on this computer (started with beef-gui / python -m beef.gui), which runs the installed beef — update beef and the GUI uses the new version.

Workflow

  • Model — 2D/3D, nodes & elements (or the generators).
  • Sections — E, A, I_y, I_z, J…, optional orientation e2.
  • Supports — constraints to ground or node-to-node ties.
  • Features — springs, dashpots, point masses and full matrices (fe.CustomMatrix).
  • Loads — nodal forces/moments: constant, ramp, or time history.
  • Analysis — pick the analysis and parameters, then ▶ Run.

Node fields in Supports, Features and Loads accept typing (1,4,7-9) or picking: click into the field, then click nodes in the view to add/remove them (Esc when done).

Running and output

Analyses run as jobs in the Python session. The drawer at the bottom shows each job's output (the same text appears in the terminal), lets you cancel jobs, and has a Python console with eldef, analysis, result, np, fe and beef.

Solver: beef uses beef's Analysis directly. sparse uses beef's element and feature matrices with sparse assembly and solvers (modal: undamped modes; linear static) — much faster for large models. auto picks sparse above DOFs for those two analysis types.

Files

.beef files hold the model as JSON (Open/Save). The Examples list shows the .beef files in the examples folder of beef.gui (and folders in BEEF_GUI_EXAMPLES). Python script exports the model and analysis as a plain beef script.

2D node: 0=ux, 1=uy, 2=rz.   3D node: 0=ux, 1=uy, 2=uz, 3=rx, 4=ry, 5=rz.
